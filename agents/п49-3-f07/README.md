# п49-3 — F-07: `at_step` + `initial_data` + `seed` + `requires` (1.12.10)

Решение `D-19` (RFC-06 §5, архитектор 2). Серия 1.12.x, патч (контракт
расширяющий; MINOR не поднимать).

## Что есть сейчас (факт)

- `begin_scene(...)` умеет `initial_data` (F-22/v1.5), но **на командном входе
  недоступна** (`router.py:162`); `SceneDefinition` не имеет `seed`
  (`scene.py:203–215`), `Step` не имеет `requires`.
- Продукт из-за этого вынужден обходить: повторная анкета не подставляет
  профиль (`bots/player/scenes/survey.py:299–305`), долг
  `bots/player/INTERNAL.md:61` переживёт патч, если не добавить `seed`/`requires`.

## Задача

1. **`SceneDefinition.seed`** — предзаполнение данных сцены при **любом** входе
   (кнопка, команда, `at_step`): callable(`UserSession` → dict) или dict;
   применяется до первого шага; значения проходят валидацию JSON (F-03).
2. **`Step.requires`** — декларативное условие применимости шага (callable от
   данных сессии → bool); если шаг недоступен — движок идёт дальше по
   `next_step_id` (или выдаёт нейтральный ответ, если цепочка пуста); **без**
   стека «назад» (снят решением).
3. **`at_step` на входе** (если ещё не полноценно): `begin_scene(..., at_step=...)`
   доступен и с командного входа — внешний вход может начать сцену с шага.
4. Тесты: seed при кнопке/команде; requires перескакивает шаг; at_step с
   команды; обратная совместимость (без seed/requires — как раньше);
   JSON-валидация seed (несериализуемое → `ConfigError`).
5. Документы: `scenes/ARCH.md`/`INTERNAL.md` (метки `ARCH-CHANGE: RfI-06-3…`),
   `router/ARCH.md` при необходимости, `docs/ARCH-CHANGE.md`, `docs/History.md`
   (v1.12.10), `scenes/TODO-ARCH.md`/`router/TODO-ARCH.md` (F-07 → внедрено).
