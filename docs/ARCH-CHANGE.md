# ARCH-CHANGE — реестр меток совета архитекторов в документации движка

> Компонентные `docs/components/<компонент>/ARCH.md` правит совет архитекторов;
> каждая правка нормы помечена `ARCH-CHANGE: RfI-NN` (регламент —
> `Room_for_Improvement/`, решение D-12, направление D2; индекс компонентов —
> [components/README.md](components/README.md)). Пакет движка вносит метку в
> ARCH по решению комнаты и регистрирует её здесь: **метка → решение → пакет →
> коммит**. Строки не удаляются — реестр показывает, какая норма когда и по
> какому решению изменилась.

| метка | дата | решение | пакет | коммит |
|---|---|---|---|---|
| `RfI-06-1` | 2026-11-04 | `D-19` (комната `engine-contracts`, RFC-06 §1): `SceneRegistry.list_scenes() -> Tuple[str, ...]` — публичные id сцен по возрастанию; норма — `router/ARCH.md` (публичный контракт, инвариант 10) | п49-1 | `e605342` (v1.12.5) |
| `RfI-06-2` | 2026-11-04 | `D-19` (комната `engine-contracts`, RFC-06 §2): `cancel_buttons` — кнопки продолжения после `/cancel` задаёт продукт (симметрия F-31), движок подписей не изобретает; норма — `app/ARCH.md` (конструктор), `router/ARCH.md` (инвариант 5) | п49-1 | v1.12.8 (этот коммит) |
| `RfI-06-3` | 2026-11-04 | `D-19` (комната `engine-contracts`, RFC-06 §5): F-07 — `SceneDefinition.seed` (посев данных при любом входе, JSON-домен F-03), `StepDefinition.requires` (callable данных → bool, пропуск по `next_step_id`, стек «назад» снят), `at_step` в `begin_scene`/`App.start_scene` (приземление «как если дошли», вне сцены — `ConfigError`); норма — `scenes/ARCH.md` (контракт, инварианты 8–9), `router/ARCH.md` (контракт, инвариант 11), `fsm/ARCH.md` (инвариант 9), `app/ARCH.md` (инвариант 4) | п49-3 | v1.12.10 (этот коммит) |
