# История версий Bot Fork

Полная хроника расширений библиотеки — от базовой v1.0 до текущего релиза,
по порядку. Правила нумерации — в [README.md](../README.md), раздел
«Версионирование». Номера **F-xx** — дыры движка из рабочего листа продукта
(«Недостающий функционал в Bot Fork.md»); там же детали и контекст находок.

---

- **v1.0** — базовый контракт: `Scene` / `Step` / `Button` / `DialogRouter` /
  `FSMEngine`; ядро не зависит от `aiogram`/`vkbottle` (NFR-03); один адаптер на
  процесс; `MemoryStateStorage`; 4096-символьная валидация вывода; Apache-2.0.

- **v1.1** — прикладной рантайм: `app.send` (F-11), async-валидаторы и `Step.action` (F-04),
  `SqlStateStorage` (F-02/03), дедупликация событий (F-18), хук `on_error` (F-20), брендинг-флаг (F-16).

- **v1.2** — вложения `Attachment` в `OutgoingMessage` (F-01, TG photo/doc, VK upload),
  `content_type` события (F-21).

- **v1.3** — запуск сцены из кнопки: payload `scene:<id>` (F-23); контекст сессии
  в `action(value, data, session)` (F-04).

- **v1.4** — групповые чаты (WP3): `chat_type` и `event_type/system_kind` в
  `IncomingEvent` (F-13), хук `on_system_event` (служебные события не будят диалог),
  операции адаптеров `create_chat`/`add_member`/`remove_member`/`get_invite_link` (F-13)
  и `send_ex`/`edit_message` (F-19). VK умеет всё; Telegram — план Б:
  `create_chat`/`add_member` бросают `PlatformOperationNotSupported`
  (чат создаёт админ, бот раздаёт `get_invite_link`).

- **v1.5** — полосы диалога и программный вход (WP4, готовим Фазу 2): `SessionKey.lane`
  («user»|«system»), `SceneDefinition.lane` — подтверждение слота перехватывает чат, анкета
  ждёт в своём слоте и продолжается с того же шага (F-06); `app.start_scene(scene_id,
  user_id, chat_id, data)` — запуск сцены из кода для jobs/outbox (F-22); схема
  `SqlStateStorage` v2 (PK с lane) с авто-миграцией старых баз.

- **v1.6** — динамические prompt'ы (F-05): `Step(..., prompt=...)` принимает `str` или
  функцию `Callable[[UserSession], str]` — карточка слота и регламент чата рендерятся из
  данных сессии в момент показа (старт сцены и каждый переход). Статический контракт
  сохранён: обычная строка ведёт себя как раньше.

- **v1.7** — завершение сцены без хардкода (F-09): `SceneDefinition.on_complete` вызывается
  вместо встроенного отчёта (текст / список текстов / `OutgoingMessage` / `None` — молча;
  async тоже ждём; исключение — фолбэк на generic-отчёт). Спец-код демо-сцены `info`
  удалён из ядра, её текст переехал в саму сцену — библиотека больше не знает бизнес-текстов.

- **v1.8** — переименование чатов (F-24): `rename_chat(chat_id, title)` в адаптерах
  (VK `messages.editChat`, TG `setChatTitle`), по умолчанию `PlatformOperationNotSupported` —
  нужно сцене `team_name` (03 §6), чтобы бот сам называл чат команды.

- **v1.8.1** — фикс DSN: `SqlStateStorage` понимал сырой путь, но падал на
  SQLAlchemy-стиле `sqlite:///dev.db` / `sqlite+aiosqlite://` (жизнь показала на
  первом живом запуске бота продукта).

- **v1.9** — `Step.info`: инфо-шаг («О проекте», «Готово»), который печатает и
  идёт дальше сам; кнопка, прилетевшая в текстовый шаг, отвечает честным
  INVALID_BUTTON вместо «Ответ не должен быть пустым» (баг живой приёмки).

- **v1.9.1** — живучесть TG-polling: сетевой отказ на старте (getMe через падающий
  прокси) не роняет процесс, переподключение через 5 с (F-26).

- **v1.10.0** — `SceneDefinition.restart_text` (F-27): шапка перезапуска сцены больше
  не вшита в ядро. Сцены, которым нужен предупреждающий заголовок («Анкета начата
  заново.»), задают его сами; `""` — молчаливый перезапуск (меню-сцены), `None` —
  нейтральное «Диалог начат заново.»

- **v1.11.0** — `Reject(text, buttons)` (F-28): отказ действия может нести свои кнопки
  (обычно launch `scene:<id>`) — отказ «команды нет» предлагает «📝 Анкета», а не
  тупик из кнопок текущего шага. Строковый отказ не изменился.

- **v1.11.1** — динамическая клавиатура (F-29): `buttons` шага — функция от сессии
  (sync/async), резолвится при отрисовке и при матчинге нажатия; async prompt.

- **v1.11.2** — текстовый побег с choice-шага зовёт обратно (F-30): новый код
  `NEED_BUTTON` и тёплый текст вместо «кнопка недействительна» (он остался только
  для впрямь устаревших payload'ов).

- **v1.11.3** — `cancel_commands` (F-31): набор команд отмены задаёт продукт
  (VK печатает «/отмена»); по умолчанию прежнее `("/cancel",)`.

- **v1.11.4** — отмена подсказывает живые команды (F-32): «Заново — <команда
  сцены>» вместо зашитого демо-«/info»; `SceneRegistry.commands_for(...)`.

- **v1.11.5** — info-шаг первым шагом сцены авто-завершается (F-33):
  `begin_scene` прогоняет стартовый info-цепочку F-25 (документ/правила из
  одного info больше не паркуют сессию и не глотают следующее сообщение);
  generic-отчёт завершения переименован из «Анкета успешно завершена» в
  «Сценарий завершён» — сцены без on_complete бывают не анкетами.

- **v1.11.6** — `StateStorage.list_scene(scene_id)` (F-34): снимок сессий,
  припаркованных на сцене, для фоновых саметчеров продукта (TTL брошенных
  анкет в TEAMWINNING); у базы — пустой список (необязательная возможность),
  реализованы Memory и Sql версии, ключ из снимка годится для `clear`.

- **v1.12.0** — **открыта серия «Технологическое закрытие F-xx + модульная
  документация»** (направление D2 плана TEAMWINNING `v0.4`, слово Мастера
  2026-11-04). В релиз входит: модульная документация по компонентам движка
  (`ARCH.md` — нормы и контракты, `INTERNAL.md` — как устроено сейчас, по
  девяти компонентам: контракт, сцены, FSM, роутинг и реестр, приложение,
  хранилище, адаптеры, витрина, документация), карта рабочих F-xx для совета
  архитекторов, точный счётчик тестов в README (158 вместо устаревших 154).
  **Код ядра не менялся: контракт v1.11.6 сохранён полностью, обратная
  совместимость полная, 158/158 зелёные.** Патчи серии закрывают дыры по
  одной: F-35 (публичный `list_scenes`), F-36 (клавиатура после `/cancel`),
  F-07 (прыжки по шагам), F-08 (пагинация/мультивыбор) — каждый со своими
  тестами и строкой ниже.

- **v1.12.1** — `bot_fork.__version__` согласован с релизом (был «1.11.6» при теге v1.12.0).
  **D2.1 (пакет п46):** `docs/components/` — три поля документации
  (ARCH — норма, INTERNAL — факт, TODO-ARCH — очередь) по девяти компонентам
  движка + индекс; в README проставлена текущая версия. **Код ядра не менялся,
  158/158 зелёные.**

- **v1.12.2** — **Д-9 (пакет п48-1):** `bot_fork.__version__` = «1.12.1» —
  константа согласована с последним оформленным патчем серии (была «1.12.0»
  при pyproject 1.12.1); факт свежести версии в `app/INTERNAL.md` обновлён.
  **Код ядра не менялся, 158/158 зелёные.**

- **v1.12.3** — **Д-2 (пакет п48-2):** generic-отчёт завершения сцены без
  `on_complete` больше не печатает значения `session.data` — нейтральная строка
  «Сценарий завершён.» вместо «Ваши ответы: • k: v», которое уводило ПДн в чат
  (норма: `docs/core/данные.md` п.7 продукта + SOUL). Сцены с `on_complete` не
  затронуты (контракт F-09 сохранён). Тесты: новый «в generic-отчёте нет
  значений данных» (`test_on_complete.py`), `test_lanes.py` переведён на новую
  норму. **Сюита зелёная: 159 закоммиченных тестов; в общем прогоне с
  незакоммиченными тестами п48-3 — 173 passed + 7 subtests.**

- **v1.12.4** — **F-03 (пакет п48-3, решение комнаты `D-18`):** `UserSession.data`
  — `Dict[str, Any]`: значения JSON-совместимые (`str | int | float` конечный `|
  bool | None | list | dict`, вложенно, ключи `str`); несериализуемое (`set`,
  `datetime`, кортеж, объект, NaN/Infinity) — `ConfigError` с адресом проблемного
  ключа при построении сессии, до хранилища. Контракт расширяющий: старые
  строковые данные — валидное подмножество, читаются как раньше (строка-обёртка
  возвращается строкой). `MemoryStateStorage` и `SqlStateStorage` проверены на
  dict/list: JSON-колонка `data` принимает составные значения без изменений
  схемы; снимки (`clone`, `list_scene`, `begin_scene(initial_data)`) копируют
  данные глубоко — вложенные структуры не alias-ятся. Продукт не тронут:
  снятие JSON-обёрток — отдельный пакет (D2.4). Тесты:
  `tests/test_session_data_json.py` (14 + 7 подтестов: домен значений,
  Memory+Sql round-trip, отказ на несериализуемом, совместимость строк).
  **Сюита зелёная: 173 passed + 7 subtests.**

- **v1.12.5** — **F-35 (пакет п49-1, решение комнаты `D-19`, RFC-06 §1, метка
  `ARCH-CHANGE: RfI-06-1`):** `SceneRegistry.list_scenes() -> Tuple[str, ...]` —
  публичные id всех зарегистрированных сцен **по возрастанию**; детерминированно,
  состояние реестра не меняет. Только id, без дескрипторов и `scene_info`:
  `title` в `SceneDefinition` нет, «на каком шаге игрок» — состояние хранилища
  (`StateStorage.list_scene`, F-34), а не знание реестра. Снимает продуктовый
  обход `getattr(app.registry, "_scenes")` (152-ФЗ-очистка `delete_account.py`;
  правка продукта — за продуктом). Норма: `router/ARCH.md` — публичный контракт +
  инвариант 10; создан реестр меток движка `docs/ARCH-CHANGE.md`. Тесты:
  `tests/test_registry.py` (5: пусто, сортировка, идемпотентность, отсутствие
  мутации, сцена без команд входа). **Сюита зелёная: 178 закоммиченных тестов
  + 7 subtests; в дереве с незакоммиченной работой п49-2 — 180 passed.**
