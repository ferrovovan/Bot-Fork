## Ключевые решения (и почему так)

| Решение | Зачем | Где |
|---|---|---|
| Факультативные операции не абстрактные, дефолт — `PlatformOperationNotSupported` | сторонние адаптеры (песочница `web/`) не падают при инстанцировании | `base.py:47-86` |
| Ленивые импорты `aiogram`/`vkbottle` внутри методов | ядро устанавливается и живёт без платформенных библиотек (NFR-03) | `telegram.py:342,512`, `vk.py:371,412-413` |
| `create_chat`/`add_member` TG бросают и в моке («возможности нельзя добавлять моками») | план B продукта (чат создаёт админ) виден с первого теста (F-13) | `telegram.py:397-414` |
| Мок-режим = нет токена; операции пишутся в `chat_ops`/`sent_messages` | продуктовые тесты без сети и токена | `telegram.py:394-447`, `vk.py:228-297` |
| Поллинг TG: цикл переподключения с паузой 5 с | старт через нестабильный прокси не убивает процесс (F-26) | `telegram.py:506-557` |
| `event_id`: `tg_{update_id|message_id}` / `vk_{id}` | сырьё для дедупа F-18 на уровне app | `telegram.py:144-293`, `vk.py:146,184` |
| VK: групповой peer ≥ 2·10⁹; локальный chat_id = peer − база | VK API ждёт локальный id чата в групповых методах | `vk.py:50,231-235` |
| VK-вложение: загрузить (`docs`), потом `messages.send(attachment=…)` | VK не принимает байты в send | `vk.py:377-404` |
| `my_chat_member` → `bot_added`/`bot_removed` по статусам `left`/`kicked` (F-13) | продукт реагирует на изгнание бота | `telegram.py:21,249-313` |
