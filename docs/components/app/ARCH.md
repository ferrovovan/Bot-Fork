# app/ARCH.md — Code Arch: какими должны быть сборка приложения и публичный API

**Компонент:** `bot_fork/app.py`, `bot_fork/__init__.py` ·
**Серия контракта:** `1.12.x` · **Правит:** совет архитекторов (метка `ARCH-CHANGE: RfI-NN`)

## Назначение

Держит: сборку приложения из частей (одна платформа, адаптер, хранилище, реестр,
роутер) и обёртку исполнения событий — дедупликация событий, хук `on_error`,
системные события в хук; программный запуск сцены (F-22) и проактивная отправка
(F-11); `__init__.py` — единая витрина публичной API библиотеки.
Не держит: логику диалога (fsm), разборы (router), знание платформ (adapters).

## Границы

| Можно импортировать | Нельзя импортировать |
|---|---|
| stdlib; модули ядра `bot_fork` | `aiogram`/`vkbottle` вообще (ленивые импорты живут только в адаптерах, NFR-03); продукт — нельзя |

## Публичный контракт

- **`BotForkApp(platform, adapter?, storage?, token?, on_error?, on_system_event?,
  dedupe_capacity?, cancel_commands?)`**; `from_env()` (env `ENABLED_PLATFORMS`,
  `TELEGRAM_BOT_TOKEN`/`VK_BOT_TOKEN`, `LOG_LEVEL`); `register_scene`; `start_scene`
  (F-22); `handle`; `send` (F-11/F-01); `run`.
- **`__all__`** пакета — витрина API ядра (типы, сцены, FSM, роутер, хранилища,
  адаптеры, исключения, `apply_branding`); состав меняется только со строкой очереди.
- Один процесс — одна платформа (`telegram`|`vk`); одновременный запуск обеих
  отказан контрактом (F-17 живёт как «не для MVP»).

## Инварианты

1. Неизвестная платформа, список платформ из `from_env`, адаптер не своей
   платформы — `ConfigError` до опроса сети. Проверяется: `tests/test_config.py`.
2. Повторный `event_id` — молчаливый пустой `HandlerResult`; событие без id
   не дедуплицируется никогда; кеш ограничен LRU-ёмкостью (F-18) —
   `tests/test_runtime_guard.py`.
3. Исключение в обработке с `on_error` — нейтральное сообщение + хук
   (синхронный или async), процесс жив; без хука — исключение наружу (F-20) —
   `tests/test_runtime_guard.py`.
4. `start_scene` запускает сцену в её дорожке, сеет `initial_data`, доставляет
   prompt адаптером; незарегистрированная id — ошибка до отправки (F-22) —
   `tests/test_lanes.py`.
5. `send` доставляет текст с кнопками и вложением напрямую, вне диалога (F-11/F-01) —
   `tests/test_send.py`, `tests/test_media.py`.
6. Демо-сцена `/info` проходит end-to-end через публичный API на обеих
   платформах — `tests/test_demo_info.py`.
7. Логи app-уровня не содержат токенов и текстов пользователей — только
   сцена/шаг/статус/время; проверяется кодом (состав логов) — прямого теста нет,
   это долг ([INTERNAL.md](INTERNAL.md)).

Где это лежит — [INTERNAL.md](INTERNAL.md).

## Запреты

- Два адаптера в одном процессе (контракт MVP; обе платформы — два процесса).
- Токены и тексты пользователей в логах; `run()` без настройки логирования.
- Расширять `__all__` за счёт продуктовых имён.
