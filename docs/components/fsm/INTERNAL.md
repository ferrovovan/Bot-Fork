## Ключевые решения (и почему так)

| Решение | Зачем | Где |
|---|---|---|
| Ответ пишется в `session.data` под ключом id шага | отчёт и `on_complete` читают данные по шагам; переименование шага = потеря данных (известный контракт) | `fsm.py:205-210` |
| Действие запускается после валидации до перехода; строка/`Reject` — отказ без сохранения данных | сервис продукта говорит «нет» раньше, чем движок сдвинет диалог (F-04/F-28) | `fsm.py:217-265` |
| Контекстное действие определяется по сигнатуре: третий позиционный аргумент → сессия | старые двухаргументные действия не ломаются | `fsm.py:32-43,221-226` |
| Два отказа choice разведены кодами: `INVALID_BUTTON` против `NEED_BUTTON` | «клавиатура устарела» и «нужна кнопка» — разные ответы для продукта (F-30) | `fsm.py:160-204` |
| Цепочка info — цикл `for _ in range(10)` (именованной константы лимита нет) | info→info по кругу не вешает движок | `fsm.py:304-342` |
| Исключение `on_complete` → лог + общий отчёт; `None` — молчание | финалка продукта не роняет диалог (F-09) | `fsm.py:344-370` |
| Водяной знак через env `BOT_FORK_BRANDING`, читается при каждом вызове | включается без перезапуска процесса; по умолчанию текст чистый | `fsm.py:27-28,46-59` |
| Переход `transitions[payload]` с откатом на `next_step_id` | кнопка без явного перехода ведёт по линии сцены | `fsm.py:268-272` |
