## Ключевые решения (и почему так)

| Решение | Зачем | Где |
|---|---|---|
| Реестр хранит два словаря (id→сцена, команда→id), уникальность проверяет `register` | коллизия команд видна на старте; `resolve_command` — O(1) | `router.py:29-58` |
| Порядок `route`: system → cancel → старт → активная сессия → служебный | отмена обязана работать при перехвате; явный старт важнее текста активной сессии | `router.py:94-205` |
| Обе дорожки читаются разом (`system_session`, `user_session`) | выбор дорожки старта зависит от сцены, а не от удачи чтения | `router.py:148-150,163` |
| Результат FSM сохраняется в дорожке самой сессии: завершение системной открывает пользовательскую (F-06) | иначе подтверждение молча проглатывает опрос | `router.py:201-213` |
| `begin_scene` — общий путь команды, кнопки `scene:` и `app.start_scene` (F-22) | один запуск = одна семантика перезапуска | `router.py:215-269` |
| `restart_text`: `None` → «Диалог начат заново.», `""` → без префикса (F-27) | продукт жаловался на «диалог» в админском меню | `router.py:246-249` |
| Подсказка отмены строится из `commands_for`/`list_entry_commands` (F-32) | демо-команды не должны течь в продукт | `router.py:118-125` |
| Стартовая цепочка info продублирована из FSM (F-33) | цепочка обязана вести себя одинаково на старте и при переходе; не вынесено — долг | `router.py:271-310`, `fsm.py:299-342` |
| Активная сессия ищется system→user инлайном (`session = system_session or user_session`) | перехват важнее; отмена снимает тем же порядком | `router.py:152-153,186-187` |
