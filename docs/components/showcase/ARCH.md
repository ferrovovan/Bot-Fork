# showcase/ARCH.md — Code Arch: какими должны быть витрина и песочница

**Компонент:** `examples/`, `scripts/build_pages.py`, `scripts/handle_event.py`,
`site/`, `web/` · **Серия контракта:** `1.12.x` ·
**Правит:** совет архитекторов (метка `ARCH-CHANGE: RfI-NN`)

## Назначение

Держит: показ движка без установки и токенов — примеры (`demo_info` — переносимая
сцена `/info`, `demo_mars_pizza` — витрина закрытых F-xx с прогоняемым сценарием),
сборку страницы GitHub Pages из живого прогона ядра (`build_pages`), браузерную
песочницу (`web/` — TS-оболочка + `handle_event.py`).
Не держит: эмуляции сценарной логики (песочница вызывает ядро), замены тестов,
доступа к приватным полям `bot_fork`.

## Границы

| Можно | Нельзя |
|---|---|
| `bot_fork` — только публичный API (как продукт); примеры — stdlib + `bot_fork`; `web/` — узел и подпроцесс `scripts/handle_event.py` | приватные имена движка (`_…`); живые токены и сеть |

## Публичный контракт

- **`python -m examples.demo_mars_pizza [--live] [--no-color]`** — скриптовый
  прогон `run_scripted(color)`; **`python -m examples.demo_info`** — демо `/info`.
- **`python scripts/build_pages.py`** → `_site/index.html`; пустой или битый
  транскрипт — остановка сборки с ненулевым кодом.
- **`python3 scripts/handle_event.py [--reset]`** — stdin JSON-событие →
  stdout JSON `HandlerResult`; состояние между вызовами — файл в
  `tempfile.gettempdir()`.
- **`web/`**: `npm run dev` — vite + `server.ts`; платформы — только
  `telegram|vk`, идентификаторы фильтруются регуляркой.

## Инварианты

1. Одна и та же демо-сцена проходит TG и VK последовательно. Проверяется:
   `tests/test_demo_info.py`.
2. Транскрипт страницы — вывод живого ядра при сборке (мок-адаптер, без сети);
   битый прогон не попадает в релиз — проверяется сборкой `pages.yml`
   (ненулевой код `build_pages`).
3. Песочница не эмулирует FSM: каждое сообщение пользователя идёт через
   `app.handle` ядра — проверяется кодом `handle_event.py`; автоматического
   теста нет (долг).
4. Примеры не лезут в приватные поля движка — автоматической проверки нет,
   держится приёмкой пакета (долг в очереди).

Где это лежит — [INTERNAL.md](INTERNAL.md).

## Запреты

- Второй реализации диалоговой логики на TS-стороне: витрина обязана показывать
  настоящее ядро.
- Ручной «текущий» транскрипт страницы — страница генерируется сборкой.
- Токенов и сети даже в «живом» режиме примеров (там только ввод человека).
