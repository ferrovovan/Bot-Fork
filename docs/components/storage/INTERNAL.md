## Ключевые решения (и почему так)

| Решение | Зачем | Где |
|---|---|---|
| Memory отдаёт `clone()` на get и на set | ни один вызывающий не мутирует состояние хранилища на месте | `storage.py:51-64`, `models.py:216-223` |
| Один `asyncio.Lock` на всё хранилище | проще per-key, а конфликт редок на масштабе сессий | `storage.py:49,57-64`, `sql_storage.py:59` |
| DBAPI через `asyncio.to_thread` | синхронный `sqlite3` не блокирует событийный цикл | `sql_storage.py:235-261` |
| Одно соединение на инстанс (`check_same_thread=False`) + лок; `connection_factory` — выбор продукта (PG) | sqlite не любит потоки; продукт уносит бэкенд без правки движка | `sql_storage.py:45-62` |
| Схема v2 с дорожкой; миграция пересозданием таблицы (SQLite не умеет менять PK) | F-06 без потери старых баз, строки v1 едут в `lane='user'` | `sql_storage.py:64-97` |
| `INSERT … ON CONFLICT DO UPDATE` — upsert | `set` идемпотентен, гонка на одном PK безопасна | `sql_storage.py:159-163` |
| Разбор DSN (`sqlite:///`, `sqlite+aiosqlite://`, 4-слэша, `:memory:`) | первый запуск продукта споткнулся о SQLAlchemy-стиль пути — фикс v1.8.1 | `sql_storage.py:25-34` |
| `data` — JSON-текст с `ensure_ascii=False`, **без** приведения к `str()` (приведения в коде нет) | читаемый дамп; домен F-03 (`Dict[str, Any]`) соблюдает конструктор `UserSession`, не хранилище | `sql_storage.py:171`, `models.py:17-49` |
| Битый `updated_at` → текущее время; битый JSON `data` **или значение вне домена F-03** (легаси-`NaN`/`±Inf`, которые принимает `json.loads`) → `StorageError`: `ConfigError` из `UserSession` конвертится на границе чтения (п49-2) | штамп времени не повод ронять диалог, данные — повод; ошибок модели домена хранилище наружу не выпускает | `sql_storage.py:132-152`, `sql_storage.py:208-230` |
